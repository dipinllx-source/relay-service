## ADDED Requirements

### Requirement: 通知类型注册表覆盖所有实际发送类型
默认通知类型注册表 MUST 包含代码中所有实际调用发送的通知类型，任何被发送的类型都不得因注册表缺键而被拦截。

`accountEvent` 属于实际发送的类型，MUST 出现在默认注册表中，并在设置页作为可切换的开关暴露给使用者。

#### Scenario: 账号事件通知可送达
- **WHEN** 系统触发一次 `accountEvent` 类型的通知且该类型开关为开启
- **THEN** 通知被投递到已启用的推送平台

#### Scenario: 账号事件开关可见可控
- **WHEN** 用户打开通知设置页
- **THEN** 通知类型列表中存在「账号事件」开关
- **AND** 关闭该开关后该类型通知不再投递

#### Scenario: 注册表与发送调用点一致
- **WHEN** 校验默认注册表的键集合与代码中发送调用点使用的类型集合
- **THEN** 每个被发送的类型都能在注册表中找到对应键

### Requirement: 注册表不含无触发源的通知类型
默认通知类型注册表 MUST NOT 包含没有任何发送调用点的类型，设置页也 MUST NOT 为此类类型提供可切换开关。

`quotaWarning`、`systemError`、`securityAlert` 在代码中无任何发送调用点，MUST 从默认注册表与设置页中移除。

#### Scenario: 无触发源类型不再出现于设置页
- **WHEN** 用户打开通知设置页
- **THEN** 通知类型列表中不含配额警告、系统错误、安全警报三项

#### Scenario: 旧配置中的遗留键被忽略
- **WHEN** 持久化配置中仍存有已移除类型的键
- **THEN** 读取配置不报错，这些键不影响任何通知投递行为

### Requirement: 类型级拦截具备可观测性
因通知类型未开启而拦截发送时，系统 MUST 输出可检索的日志记录，包含被拦截的类型名，使拦截行为不再静默。

#### Scenario: 拦截时留下日志
- **WHEN** 某类型通知因开关关闭而被拦截
- **THEN** 日志中出现包含该类型名的拦截记录

#### Scenario: 正常投递不产生拦截日志
- **WHEN** 某类型通知的开关为开启且投递成功
- **THEN** 日志中不出现该次发送的拦截记录
