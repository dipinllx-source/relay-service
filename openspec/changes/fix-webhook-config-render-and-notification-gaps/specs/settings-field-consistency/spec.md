## ADDED Requirements

### Requirement: 可编辑配置项必须真实生效
管理台暴露为可编辑的配置项 MUST 被后端真实读取并影响运行行为；写入后从不被读取的字段 MUST NOT 作为可编辑项呈现。

webhook 的全局重试超时字段从不被读取，实际超时一律取平台级配置，因此该输入项 MUST 从设置页移除，超时语义 MUST 收归到平台级配置。

#### Scenario: 全局超时输入项不再暴露
- **WHEN** 用户打开通知设置页的高级设置
- **THEN** 页面不含全局「超时时间」输入项
- **AND** 仍保留真实生效的最大重试次数与重试间隔两项

#### Scenario: 平台级超时仍然生效
- **WHEN** 某推送平台配置了自身的超时值
- **THEN** 向该平台发送通知时使用该平台的超时值

#### Scenario: 未配置平台超时时使用默认值
- **WHEN** 某推送平台未配置超时值
- **THEN** 发送时使用系统默认超时值

### Requirement: 说明文案不得与计算逻辑矛盾
设置页的说明文案 MUST 与后端实际计算逻辑一致；当某字段不参与计算时，MUST NOT 用文案暗示它决定计算结果。

服务倍率的基准服务字段不参与任何计费计算，因此 MUST NOT 继续作为配置项提交，其说明 MUST 改为不依赖该字段的静态文案。

#### Scenario: 倍率说明不再声称由某字段决定基准
- **WHEN** 用户打开服务倍率设置页
- **THEN** 说明文案不含「以某服务为基准且其倍率为 1.0」这类可被配置推翻的断言

#### Scenario: 修改任意服务倍率后说明保持正确
- **WHEN** 用户将任一服务的倍率改为非 1.0 并保存
- **THEN** 页面说明文案仍然与实际计费逻辑相符

#### Scenario: 保存倍率不再提交基准字段
- **WHEN** 用户保存服务倍率配置
- **THEN** 提交的数据不含基准服务字段
- **AND** 各服务倍率值被正确持久化且计费按各自倍率换算
