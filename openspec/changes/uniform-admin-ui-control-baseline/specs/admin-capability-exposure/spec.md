## ADDED Requirements

### Requirement: 未启用能力的路由不予注册
依赖能力开关的页面 MUST 仅在该能力启用时注册路由；能力未启用时 MUST NOT 可通过直接输入地址到达。

路由注册条件 MUST 与导航项注入条件保持一致，MUST NOT 出现导航不显示而路由仍可达的状态。

#### Scenario: 未启用时地址不可达
- **WHEN** 用户体系未启用且用户直接输入用户管理页地址
- **THEN** 请求落到未找到状态，不渲染该页面内容

#### Scenario: 启用后路由与导航同时出现
- **WHEN** 用户体系启用
- **THEN** 用户管理页可通过导航进入，直接输入地址亦可到达

#### Scenario: 路由与导航条件一致
- **WHEN** 检查依赖能力开关的页面
- **THEN** 其路由注册条件与导航注入条件引用同一开关状态

### Requirement: 依赖未启用特性的界面元素不渲染
依赖未启用特性的表格列与字段 MUST NOT 渲染，MUST NOT 以空值或占位文本占据列位。

#### Scenario: 依赖特性未启用时列不出现
- **WHEN** 用户体系未启用
- **THEN** 列表中不出现依赖该体系的所有者与创建者列

#### Scenario: 永不成立的分支不予保留
- **WHEN** 某条件分支在当前数据形态下永不成立
- **THEN** 该分支不作为可见界面元素保留

### Requirement: 当前页在导航中正确高亮
导航 MUST 高亮与当前路由对应的项；MUST NOT 出现停留在某页时高亮另一无关项的情况。

#### Scenario: 高亮项与当前页一致
- **WHEN** 用户停留在任一已注册的管理页
- **THEN** 导航中高亮的项与该页对应

#### Scenario: 无对应导航项时不误标高亮
- **WHEN** 当前页在导航中无对应项
- **THEN** 导航不高亮任何无关项
